# UI導線改善方針

作成日：2026-08-10

## この文書の目的

東京予算ラボは必要な部品をほぼ実装し終えているが、利用者が「いまどこにいて、次にどこを読むのか」を判断しにくい。この文書は、その原因をコード上の根拠とともに記録し、改修の順序と今回の実施範囲、および変更に伴う製品判断を残す。

対象は情報の見つけやすさと移動手段である。予算データ、証拠区分（`fact` / `case_fact` / `interpretation` / `unknown`）、固定総額の不変条件は変更しない。

## 診断

### 1. グローバルナビが1ページにしか存在しない

`.topbar` と `<footer>` は `app/page.tsx` の内部に直接書かれており、`app/layout.tsx` は `{children}` を返すだけである。結果として `/budget/[categoryId]`、`/budget-process`、`/participation`、`/sources`、`/about`、`/fiscal-context` の6ページにはサイト共通のナビゲーションとフッターが存在しない。

各ページの移動手段は「← トップへ戻る」1本に限られ、詳細ページから別の分野や別のテーマへ横移動できない。読む順序の設計以前に、7ページのうち6ページで現在位置と移動先が失われている。

### 2. 戻る導線が本文より極端に小さい

`.budgetDetailHeader>a`（`← 予算に戻る`）は `font-size:11px`。直下の `h1` は `clamp(36px,5vw,64px)` で、同じ視界の中で5〜6倍の差がある。ページ末尾の `.budgetDetailBack a`、`.budgetProcessNext a`、`.participationPageBack a`、`.sourcesPageBack a`、`.aboutPageBack a`、`.fiscalContextBack a` も11〜12pxである。

最小タップ領域（`min-height:44px`）は `@media (max-width:620px)` の中でしか指定されておらず、デスクトップでは行の高さのみで決まる。

### 3. 予算成立過程がクリックしないと読めない

トップの `.process` セクションは `openStage` の初期値が `null` で、6つのボタンを押すまで `.stageExplainer` に何も表示されない。開いても一度に1段階しか読めないため、「要求→査定→予算案→議決→成立」という順序そのものが画面に出ない。

一方 `BUDGET_PROCESS_SUMMARY_STEPS` の要約は6件すべて28〜50字であり、常時表示しても収まる。`/fiscal-context` には `.fiscalContextFlow`（`1fr auto 1fr auto 1fr` のグリッドと `>i` の矢印、狭幅で90度回転）という図のパターンが既にあるため、流用できる。隠すことで得ている利点がない。

### 4. トップに要素が多すぎる

トップは、ヒーロー（概要カード3枚）、シミュレーター（注意書き＋3指標＋9行＋右パネル）、予算成立過程（6アコーディオン）、財政前提（カード3枚＋CSVバッジ）で構成される。

右パネル `.contextPanel` の内部は7ブロックある。分野名と金額比較／そもそも何のお金／配分を変える方法／国内外の事例／東京都で現在の金額になった背景（`details`×5）／意見を伝える先／公開情報だけでは判断できないこと。これは `/budget/[categoryId]` とほぼ同じ範囲であり、トップが他ページの要約になっている。

裏付けが2つある。`.contextPanel` は `position:sticky; top:140px` だが実際の高さは数画面分あり、sticky が意図した「操作の横で読める」状態になっていない。また `@media (max-width:620px)` で `.contextPanel { display:none }` としており、モバイルではこの7ブロックを不要と判断済みで `/budget/[id]` へ送っている。

### 5. 文字サイズに強弱がない

`app/globals.css` の `font-size` 宣言は 10px が37件、11px が36件、9px が35件、8px が20件で、11px以下に集中している。大きいのは `h1`（30〜44px）と `.contextPanel>h2`（31px）程度で、中間の階層が存在しない。何が主役か判別できない原因は配置より前に文字の階層にある。

## 改修方針と着手順

小さく効いて壊れにくい順に並べる。

1. **共通ヘッダー・フッターを `app/layout.tsx` へ移す。** 情報を消さずに移動手段を回復するため、最初に行う。
2. **戻る・詳細リンクの文字サイズと当たり判定を拡大する。** 既存の導線を見つけやすくするだけで、構造を変えない。
3. **予算成立過程の6段階を常時表示の図にする。** 隠れている既存情報を出す。
4. **右パネルの後半4ブロック（事例／資料段階タイムライン／参加先一覧／判断できないこと）を既存ページへ戻す。** 唯一の大きなIA判断であり、合意の上で別途行う。
5. **本文の文字サイズ基準を14〜16pxへ引き上げる。** 全ページのCSSに触るため最後に行う。

今回の実施範囲は 1〜3 である。4 と 5 は未着手とし、着手前に改めて合意を取る。

## トップの目標構成（4 と 5 を含む最終形）

- ヘッダーとフッターは全7ページ共通
- ヒーローは総額1つと問い1つ。都税カードは `/fiscal-context` へ
- シミュレーターは配分可能額を主役指標にし、9行は1行1導線で `/budget/[id]` へ
- 「意味」は3ブロックまで（何のお金／増減の論点／次に読む先）
- 予算成立過程は常時表示の図、詳細は `/budget-process`
- 財政前提は見出しと1行に圧縮、CSVバッジは `/sources` へ
- ページの締めは詳細か参加先

読む順（配分→意味→過程→参加）は変えない。変えるのはトップが担当する範囲である。

## 製品判断の記録

### グローバルナビの「声を届ける」から `?category=` を外す

移動前のナビは `/participation?category=${selected}` で選択中の分野を引き継いでいた。ヘッダーを `app/layout.tsx` へ移すと、トップのシミュレーター状態を参照できないため、この引き継ぎは成立しない。

判断：グローバルナビは `/participation` を指す。分野を引き継ぐ導線は、トップの右パネル（`.participationDetailLink`）と `/budget/[categoryId]` の関連ナビに残る。`/participation` は分野未指定時に「予算シミュレーターで分野を選ぶと、主な所管局を引き継いで表示します」と案内する空状態を既に持っているため、情報は失われない。

7ページのうち6ページで移動手段が失われている問題の解消を、ナビ1本の分野引き継ぎより優先する。

### ナビの現在位置表示（`.active`）を一旦持たない

移動前は「予算シミュレーター」だけが `<button>` で、クリックでスクロールし、`.active` の下線が付いていた。他の3項目はページ遷移で、同じ見た目の中に異なる操作が混在していた。

判断：4項目すべてを `next/link` のページ内リンクに統一し、現在位置の下線は今回持たない。サーバー側のレイアウトで現在パスに応じた強調を行うには追加の仕組みが必要で、今回の目的（移動手段の回復）から外れる。統一により、見た目が同じものは同じ挙動になる。

### 予算成立過程のアコーディオンを廃止する

判断：トップでは6段階の番号・名称・要約を常時表示し、`openStage` の状態と `.stageExplainer` を削除する。段階ごとの公式資料や10段階の詳細は `/budget-process` が担当する。トップの役割は「順序があること」を見せることに絞る。

### 戻る導線の下限値

判断：戻る・詳細リンクは `font-size` を14px以上、`min-height` を44px以上とし、44pxの下限はモバイル専用の指定ではなく全幅で適用する。本文全体の基準引き上げ（方針5）はここには含めず、移動に使うリンクだけを先に直す。

## 検証方法

- `node --test` … レンダリング結果とCSSに対する検証。7ページすべてに共通ナビとフッターが出ること、戻る導線が下限値を満たすこと、6段階が操作なしで表示されることを回帰として残す。
- `npm run lint`
- `npm run build`
- `npm run audit:layout` / `npm run audit:demo` … ポート9223でChromeを起動した環境が必要。実ブラウザでの見た目と2分デモの通過確認は、この環境が用意できるときに行う。

#### 参加先はリンクを残す

判断：所管局の一覧と4制度の公式案内はトップから外し、`/participation?category=` へ分野を引き継ぐ1行リンクと「提出による予算への反映は保証されません」の一文だけをパネルに残す。参加への入口をトップから完全に失わせないためである。制度ごとのできること・できないことは `/participation` と `/budget/[categoryId]` が担当する。

リンクの文言は「この分野の参加制度と所管局を見る」とし、詳細ページの見出し「意見を伝える先」とは区別した。同じ言葉が2か所にあると、どちらが本体か分からなくなるためである。

#### 検証の移設について

トップのパネルを検証していた4つのテストは削除ではなく移設した。旧テストは同じ内容が詳細ページ側の既存テストで検証されていることを確認した上で取り除き、代わりに「トップは持たない」「詳細ページが持つ」の対で書き直した。検証項目は減っていない。

#### パネルの高さ制御

4ブロックを外してもなお、用途5件・検討例4件の福祉や教育、縦768pxの環境、ブラウザ拡大時には1画面に収まらない。そのため `max-height:calc(100vh - 156px)` と `overflow-y:auto` を入れ、`overscroll-behavior:contain` でページ側へのスクロール連鎖を止め、`tabIndex={0}` でキーボードからもスクロールできるようにした。

順序を逆にしなかったのは、内容を減らす前に内部スクロールを入れると、数画面分を覗き窓に押し込むだけで見えない情報が残るためである。

検証結果：`npm run build` 成功、`node --test` 108件すべて成功、`npm run lint` 指摘なし。

残りは方針5（本文の文字サイズ基準を14〜16pxへ）で、着手前に合意を取る。

### 2026-08-10：パネルの高さ制御による不具合を修正（`audit:panel`）

利用者から「詳しく見るが押せない」という報告を受け、実ブラウザで測定した。

| 画面 | パネル上端..下端 | 内部あふれ | 詳しく見る | 可視 |
| --- | --- | --- | --- | --- |
| 1440x900 | 338..1082 | 114px | 1122..1168 | × |
| 1366x768 | 338..950 | 246px | 1122..1169 | × |
| 1280x720 | 338..902 | 294px | 1122..1168 | × |

原因は `max-height:calc(100vh - 156px)` が「パネル上端が `top:140px` に固定されている」ことを前提にした値だったこと。実際の上端はスクロール前は流れの位置（338px）にあり、パネル下端が画面下端より182px下へはみ出す。さらに `詳しく見る` はパネルのクリップ境界より下にあり、内部スクロールとページスクロールの両方をしないと到達できなかった。Windowsでは画面下端のタスクバー付近に押し出されて押せない状態になる。

判断：パネルを固定ヘッダ・スクロール本文・固定フッタの3層にする。

- `.contextPanel` は `display:flex; flex-direction:column` とし、自身は `overflow` を持たない
- `.contextPanelHead`（分野名と金額比較）と `.contextPanelFoot`（参加制度リンクと詳しく見る）は `flex:none` で常に見える
- `.contextPanelBody`（何のお金・配分を変える方法）だけが `overflow-y:auto` と `overscroll-behavior:contain` を持ち、`min-height:0` で縮める
- 下端の余白を確保するため上限を `calc(100vh - 180px)` にする
- キーボードでのスクロール対象は本文なので、`tabIndex` と `aria-label` は `.contextPanelBody` へ移す

主要な次の行動をスクロール領域の外に出すことが本質的な修正である。修正後の測定値は下端の余白が3画面すべてで40px、固定後の `詳しく見る` は常に可視、クリップは発生しない。

再現手段として `npm run audit:panel` を追加した。デバッグポート9223のChromeとローカル開発サーバが必要で、3解像度×3項目を実ブラウザで確認する。方針5で本文の文字サイズを変えるとパネルの高さが再び変わるため、その前後で実行する。
